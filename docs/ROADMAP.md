# Идеи следующих улучшений PCWatch

Приоритет — точность, безопасность и низкое потребление ресурсов. Любые действия с процессами, автозагрузкой и настройками Windows должны оставаться явными и обратимыми.

## 1. Анализ автозагрузки

- Программы из Run/RunOnce, папки «Автозагрузка», службы и планировщик.
- Влияние на старт: фоновые процессы, среднее потребление после входа, издатель и подпись.
- Метки «можно отложить», «нужно для устройств/синхронизации/безопасности».
- Отключение только после подтверждения и с возможностью восстановить прежнее состояние.

## 2. Сетевая активность процессов

- Скорость и соединения по PID через IP Helper и, при необходимости, краткий ETW-сеанс.
- Адреса без содержимого пакетов, отображение только по команде пользователя.
- Пометки необычно активных фоновых программ и загрузок.

## 3. История инцидентов и сравнение состояний

- Локальная временная шкала: перегрев, высокая задержка диска, DPC-всплески, нехватка памяти.
- Сравнение «до / после» с одинаковой длительностью замера.
- Экспорт снимков JSON/CSV и повторное открытие их в PCWatch.

## 4. Более точные датчики оборудования

- Дополнительный необязательный адаптер к уже установленному LibreHardwareMonitor/HWiNFO.
- Не устанавливать и не загружать сторонние драйверы вместе с PCWatch.
- Температуры CPU/GPU, скорость вентиляторов, лимиты мощности — только если пользователь включил соответствующий источник.

## 5. Контекстные профили

- Профили «Работа», «Игра», «Аудио», «Экономия заряда» с разными порогами предупреждений.
- Для аудио: акцент на DPC/ISR, страничных ошибках и задержках планировщика.
- Для игр: GPU/VRAM/частота/фоновые загрузки, без неоправданного изменения системных настроек.

## 6. Обучаемая базовая линия

- Персональные нормы по времени суток и сценарию нагрузки.
- Аномалии относительно собственной истории компьютера, а не универсальные «оптимальные» проценты.
- Объяснимая аналитика: всегда показывать исходные измерения и причину оценки.

## 7. CLI и плановые отчёты

- `PCWatch.exe --report 60 --output report.html` для диагностики без открытия GUI.
- Режим для техподдержки с минимальным набором данных и явным выбором включать ли пути процессов.
- Проверка exit code для автоматизации.

## 8. Улучшения интерфейса

- Сохраняемые раскладки карточек, избранные процессы и закреплённые метрики.
- Компактный always-on-top виджет с ручным выбором 2–4 показателей.
- Больше клавиатурных команд, высококонтрастная тема и подробные описания для screen reader.
- Ручная проверка новых версий без телеметрии; подписанные релизы при наличии сертификата.

Не планируется: скрытая телеметрия, «ускорение в один клик», очистка реестра, автоматическое завершение приложений, отключение защиты Windows или установка собственного kernel-драйвера.
